# Ограничения браузера и честные ограничения проекта

## 1. Бот живёт ТОЛЬКО пока открыта вкладка (TAB-LIFETIME)

- Закрытие вкладки → `pagehide` → `bot.stop()` → транспорт закрывается →
  сервер получает разрыв UDP-сессии и снимает игрока с онлайна в течение ~10–30 сек.
- Сворачивание в фоновую вкладку: браузеры троттлят таймеры (до 1 раза/мин),
  поэтому heartbeat 5 сек станет нерегулярным, а сервер может кикнуть по timeout.
  Мы останавливаем бота при `visibilitychange → hidden` явно — чтобы не держать
  «полумёртвый» сокет на сервере. Это осознанный дизайн, а не баг.
- **Нельзя** обойти это без service worker / Web Push / VPS — и мы этого не делаем:
  проект принципиально No-VPS и «одна вкладка = один бот».

## 2. Браузер не умеет UDP

WebTransport datagrams работают только поверх HTTP/3 (QUIC) и только между
браузером и *нашим* сервером. Поэтому стек:

```
Browser ──(WebTransport или WebSocket)──▶ Edge Proxy ──(UDP)──▶ SA-MP server
```

Прокси пересылает байты 1-в-1; никакого парсинга RakNet на прокси нет —
это сохраняет совместимость с 0.3.7 и CRMP 0.3e и упрощает деплой.

## 3. HTTPS обязателен

WebTransport и WebSocket(wss) требуют TLS-сертификата — все три платформы
(Tatnet/Layer0/Onreza) выдают его автоматически. На `http://localhost`
работает WS-fallback для разработки.

## 4. Лимиты прокси (anti-DDoS)

- максимум **5 одновременных сессий с одного IP**;
- whitelist портов цели: 7777, 3694, 8192, 7778;
- TTL простой сессии — 90 секунд (автозакрытие мёртвых UDP-сокетов).

## 5. Протокольные допущения

См. docs/PROTOCOL.md — mangle/AWC ключи, ACK-битмапы, отсутствие полного
CLIENT_SYNC. На серверах с агрессивной anti-cheat защитой (DD2, custom AFC)
логон может не пройти: это ограничение открытой реализации протокола,
а не транспорта.

## 6. Правовая оговорка

Проект для образования и личных экспериментов. Удержание онлайна может
нарушать правила конкретного сервера — спрашивайте разрешение у администрации.
